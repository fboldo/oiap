```sh
npx oiap build oiap.plugin.ts --out dist/oiap
```

## Two ways to ship

<CardGrid>
	<Card title="Commit host files with oiap sync" icon="github">
		Run `oiap sync`, commit the generated files, and let the OIAP GitHub Action fail pull requests that are out of date. Users install with each host's own command, such as `claude plugin marketplace add owner/repo`.

		[Ship with oiap sync](/oiap/guides/oiap-sync/)
	</Card>
	<Card title="Build at install time" icon="rocket">
		Users run `npx install-agent-plugin owner/repo --plugin <id> --agent <target>`, which builds the bundle from your source on their machine. Or wrap `installPlugin()` in your own CLI.

		[Use install-agent-plugin](/oiap/guides/install-agent-plugin/)
	</Card>
</CardGrid>

Most plugins use both. See [Two ways to ship a plugin](/oiap/start/two-ways-to-ship/).

:::note
OIAP is early and actively evolving. Every build writes a [capability report](/oiap/guides/capability-reports/) that says what mapped natively, what degraded and what is unsupported for each target.
:::
